# re:verse DS — AI-ready дизайн-система

*Pragmatica · демо · октябрь 2026*

## Одной фразой
Дизайн-система, на которой Claude собирает банковские экраны и целые флоу прямо в Figma: по тексту, по брифу, при клиенте. Он берёт только наши компоненты и токены, соблюдает правила продукта и сам проверяет результат.

## Зачем это клиенту
- **Скорость.** Экран по описанию собирается за несколько минут, флоу из трёх экранов — за десятки минут. Дизайнер тратит время на решения, а не на перетаскивание инстансов.
- **Консистентность.** Агент не может «чуть подвинуть» цвет или отступ: всё привязано к токенам, а аудит ловит отклонения.
- **Масштаб бренда.** Одна переменная перекрашивает всё: цвета действия и акцента, скругления, шрифты. Ваш бренд встаёт на ту же систему за минуту.
- **Знания не теряются.** Правила продукта («зелёный только у поступлений», «нет экранов успеха», «одна Primary на экран») записаны так, что их читает и человек, и агент.

## Как это устроено: четыре слоя

### 1. Figma, понятная машине
- **8 коллекций, ~210 переменных** в три слоя: примитивы (скрыты) → семантика по ролям (`text/secondary`, `border/subtle`) → роли компонентов. У каждой переменной есть scope, code syntax для Web и iOS и описание роли.
- **Три переключателя:**
  - `Color` — light / dark;
  - `Theme` — бренд: re:verse или демо-бренд Atlas (navy, Manrope, скругления 12);
  - `Spirit persona` — характер AI-ассистента: neutral, analyst, trickster, caregiver. Он меняет свечение (`glow/1–5`) и тон фраз (`voice/*`).
- **~60 компонентов** с описаниями, свойствами и состояниями. Всё, что агенту можно менять, вынесено в свойства, поэтому ему не нужно отсоединять инстанс.
- **12 эталонных экранов** `*_example` и демо четырёх характеров. Агент находит их поиском и собирает свои экраны по образцу.
- **Структура файла:**
  - Cover;
  - Foundations: тема, цвета, шрифты, отступы, матрица режимов;
  - Components: 8 секций с описаниями;
  - Examples;
  - Polygon — место, где работает агент.

### 2. MD-пакет — инструкции для агента
```
CLAUDE.md          жёсткие правила продукта и порядок работы
llms.txt           индекс: что читать под задачу
foundations/       токены, темы, типографика, голос и персоны, данные персонажа
components/        по файлу на компонент: когда брать, свойства, правильно/неправильно
recipes/           рецепты экранов: главная, счёт, карта, выбор, перевод, ответ в чате
scenarios/         флоу из брифа (Split bill)
state/             реестр id и ключей Figma
```
Принцип: много коротких файлов и императивные правила, а критичные помечены `IMPORTANT`.

### 3. Skills — повторяемые сценарии работы
- **build-screen** — экран по тексту: рецепт → поиск компонентов → сборка → аудит → отчёт.
- **build-flow** — флоу из брифа: бриф → данные и крайние случаи на бумаге → экраны → аудит → строгое ревью отдельным агентом.
- **audit-screen** — проверка любого макета: найти захардкоженные цвета, тексты без стилей, отсоединённые компоненты и нарушения правил, затем исправить.

### 4. Проверка качества
- **Скрипт аудита**, одинаковый для всех. Он считает долю инстансов и находит сырые цвета, тексты без стилей, заглушки, лишнюю Primary, неверный режим чата.
- **Рубрика на 20 баллов** и 15 типовых клиентских запросов.
- **Журнал прогонов.** Каждая найденная ошибка агента чинится в системе или в документах, а не в промпте.

## Как проходит живое демо (15 минут)
1. **Экран по тексту.** «Подтверждение перевода €40 Анне». Claude читает правила, находит рецепт и компоненты, собирает экран на Polygon и показывает отчёт аудита.
2. **Смена бренда.** Выделяем экран и переключаем `Theme` на Atlas: меняются цвета, скругления и шрифты, разметка не ломается.
3. **Характер ассистента.** Переключаем `Spirit persona`: меняются свечение и тон фраз (приветствие, подтверждение, успокаивающая фраза).
4. **Флоу из брифа.** «Разделить ужин €84 на троих». Получаем три экрана: выбор людей, суммы, транзакцию после запроса. Без экрана успеха, с Undo.
5. **Аудит чужого макета.** Claude находит нарушения в произвольном экране и чинит их.

## Результаты прогонов
| Прогон | Кто | Результат |
|---|---|---|
| Подтверждение перевода €40 | свежий агент, только по документам | 19/20, аудит без ошибок |
| Ответ Spirit: пополнить цель €100 | свежий агент, только по документам | 18/20, аудит без ошибок |
| Флоу Split bill, 3 экрана | build-flow, проверка глазами | ~17–18/20, аудит без ошибок |

Каждый прогон находил слабые места системы: спрятанную вторую Primary в шапке, чекбоксы, которые нельзя снять, невидимые подсказки на белом. Всё найденное исправлено в компонентах и документах. Подробности в `evals/log.md`.

## Ограничения (честно)
- Визуальное качество и характер бренда остаются за дизайнером: агент собирает по системе, но не придумывает новый визуальный язык.
- Plugin API не держит режим наложения на заливке, привязанной к переменной. Поэтому iOS-клавиатура в нашей копии не на токенах.
- Новые описания попадают в поиск только после повторной публикации библиотеки (делает человек).
- В части старых чат-компонентов нет текстовых свойств. Ключевой `Answer / Lead` уже переделан.
